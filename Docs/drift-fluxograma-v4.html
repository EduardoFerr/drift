📤 Escrita — publicar um post
1
UI
SubpostEditor: user digita texto, opcionalmente upload imagem, marca content-warning se quiser
2
Upload
upload.ts comprime localmente (1920px, EXIF strip) → POST nostr.build com retry exp+jitter
3 retries · base 2s
3
Negócio
handlePublish chama protocol.createPost com subposts + tag content-warning opcional
4
Protocolo
signDriftEvent: kind=9078, tags=[d, drift-version, client, content-warning?, location?], content=JSON({subposts}) · Schnorr secp256k1
5
Transporte
wssTransport.publish → 4 relays clearnet em paralelo (Promise.allSettled)
6
Volta
Mesmo evento volta pelo subscribe ativo (sync.ts) → onNostrEvent
7
events.ts
kind check → schema check → verify Schnorr → INSERT OR IGNORE → invalidateFeed
~150ms total
8
UI
useFeedStore re-renderiza · post aparece no Feed; applyContentFilters decide blur/hide
Optimistic UI usa useState local, NUNCA escreve no SQLite (invariante #2). Quando o evento real volta, o optimistic é descartado silenciosamente.

⚠ Report — moderação reativa (manifesto §26)
1
UI

2
Protocolo
reportPost(k:9081, tags=[e, p, reason]) → publish
3
events.ts
persistReport → INSERT reports(post_id, reporter_pub, reason, weight) → maybeModerate(postId)
4
moderation.ts
aggregateReports + countActiveUsers → getReportThreshold(activeUsers, reason). 'illegal' tem threshold 2x menor
5
SQLite
Se threshold atingido → UPDATE posts SET score = -999 (esconde do feed default — NÃO apaga)
6
UI
Feed query WHERE score > -999 remove naturalmente. Cliente alternativo pode exibir mesmo assim
Cliente NÃO escaneia conteúdo automaticamente (manifesto §25). Cliente NÃO deleta dados moderados do SQLite (invariante #13). O evento permanece nos relays — moderação é flag local, não delete global.
