## §3 Causa raiz da falha de persist

```
Runtime error encountered: EPERM, Permission denied:
  \\?\C:\Users\Eduardo\AppData\Local\Temp\lighthouse.79703522
Error: EPERM, Permission denied: ...
    at rmSync (node:fs:1222:18)
    at Launcher.destroyTmp (chrome-launcher.js:367:9)
```

**Diagnóstico:** chrome-launcher tenta remover o user-data-dir efêmero em `%TEMP%\lighthouse.NNN`. No sandbox de execução do agent (Windows), `%TEMP%` herda ACL restritivas que recusam `rmSync` mesmo após o Chrome ter encerrado (PID já killed). Bug conhecido em [GoogleChrome/chrome-launcher#308](https://github.com/GoogleChrome/chrome-launcher/issues/308).

**Workarounds:**
1. **CI (preferido):** rodar `lhci` no GitHub Actions (Ubuntu). `.github/workflows/lighthouse.yml` já existe — basta push pra branch com PR.
2. **Local fora-sandbox:** rodar `npm run lhci` direto no PowerShell do user, sem sandbox.
3. **Manual:** `npm run preview` + `npx lighthouse http://localhost:4173 --view` (gera report HTML direto, sem chrome-launcher cleanup).

Recomendação: deferir métricas exatas LCP/INP/CLS/TBT pra próximo CI run (PR de Batch A já vai disparar workflow). Bundle deltas estão sólidos sem isso.
